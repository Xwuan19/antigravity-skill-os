# Course architecture

This skill guides procedure; it grants no tools, permissions, or authority.

Help the teacher structure learner profiles and/or a coherent individual or class course syllabus, as requested by the teacher. Work from context the teacher provides and relevant data returned by authenticated tools within their documented scope. Treat generated content as a reviewable proposal. Keep each learner's profile individual; for a class syllabus, account for shared course goals and learner differences the teacher supplies. Ask which learners need individual profiles or syllabuses when that scope is unclear.

## Procedure

1. Clarify whether the request is for a profile, syllabus, or both. Identify goals, current and target level only when supplied, real communication situations, needs, preferences, and relevant constraints.
2. Separate supplied evidence, assumptions to confirm, and proposed pedagogical decisions. Do not invent a level, goal, need, or personal trajectory.
3. For a profile, organize known level, goals, communication situations, supports, preferences, constraints, and a brief summary. Exclude contact and financial details.
4. For a syllabus, work backward: define observable learning outcomes and the evidence that will show them before organizing modules and activities. Anchor outcomes in relevant "can do" descriptors; mark any objective inferred from a supplied program as **INFERRED — TEACHER VALIDATION NEEDED**. State the learner's current position only when supported by teacher-provided or authenticated tool data.
5. Check coherence among the requested profile and/or syllabus, modules, outcomes, evidence, level, and current position. Historical material is a reference, not automatic approval or truth.
6. Label outputs **PROFILE PROPOSAL** and **SYLLABUS PROPOSAL**. Never claim that a version was saved, approved, or published without evidence from the teacher.
7. Apply [action confirmation](references/action-confirmation.md), [draft review](references/draft-review.md), [operational safety](references/operational-safety.md), [language context](references/language-context.md), [learning context](references/learning-context.md), and [course design foundations](references/course-design-foundations.md).

## Domain boundaries

A study plan, task, and lesson are distinct artifacts with their own procedures. Avoid unnecessary identifying details in learner-facing material; use fictional names in examples.

## Completion criterion

Finish when the requested artifact is complete: a profile, a syllabus, or both. For a syllabus, connect outcomes to evidence and progression; mark gaps and inferred objectives for teacher review.
